commands::conform::correct | holds | The code calls reader.tie and reader.tests, writes the tie evidence to the ledger through Store::replace("reader:"), counts the untied subject pieces, and returns 1 exactly when a tie differs or a subject piece is untied (0 otherwise, Err when it could not run); the stated `uses` are both called and are not marked `only`, so the extra Store calls do not contradict it.
commands::conform::deterministic | fails | The result also depends on disk state the model does not let it use (only Reader::tie and Reader::tests are listed): with the same s, built, rev and reader, a ledger file that is missing, malformed or has two blocks on one line makes Store::replace return Err where a clean ledger gives Ok(0), and Store::source re-reads the model files likewise.
commands::check_rev::correct | fails | check_rev("a'b") is Ok although the prose refuses a revision that holds quotes (only `"` is tested), and check_rev("abc\\") is Ok although a trailing backslash escapes the closing quote when stamp writes `rev "abc\"` into the ledger, which defeats the stated reason for the check.
commands::check_rev::deterministic | holds | check_rev is a pure function of its string: it reads no state and its only output is Ok or an Err message built from the argument.

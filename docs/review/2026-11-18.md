# Review list for 2026-11-18

What was built overnight, and what to look at together. Increments are in
order; each one was tested and reviewed by a red-team agent before it was
pushed to main.

## Decisions taken alone

1. **Verdict output** prints `domain := Bool`, not `univ` as the design doc
   sketched: the type name says more. (lean-syntax.md notes the difference.)
2. **Golden files were converted by a program** (old parser + new printer),
   keeping comments. Expected results were translated by a script, so the
   values are the hand-written ones; only their spelling changed.
3. **Unicode only**: `∀ ∈ ∪ ∩ ¬ ×ˢ` have no ASCII spelling yet (open
   question in lean-syntax.md).
4. **`evidence c at 1`** with no arguments means the claim on its whole
   domain (was `c(_, _) holds`).
5. **`f args = g`** with a bare function name `g` still means `g` applied to
   the same inputs. It is not Lean-like; kept because the evaluator has it.

6. **Store layout**: one `.mitra/` folder with `model.mitra` and one
   append-only `evidence.mitra`, merged by git's `union` driver, rather than
   the `.mitra/evidence/` folder or git notes in workflow.md. Simplest that
   merges cleanly.
7. **Provenance as Lean-style attributes**: `@[source "ci", rev "3f2a"]
   evidence …`. Recorded, not used by verdicts yet (no staleness yet).
8. **`mitra add` does not read git**: `--rev` is explicit. Predictable, and
   no hidden dependency on git.

## Increments

### 1. Lean-inspired syntax and grammar checks (b5e63ed, 127edd3)

What to review:
- `docs/reference/language.md`: lexical rules, grammar, commands, output.
- `tests/golden/*`: read two or three converted cases (e.g. `minus/strict/03`).
- `crates/mitra-grammar/src/mitra.ll1` and `mitra.lalrpop`: the grammar in
  both forms.
- `crates/mitra-grammar/mitra/parser.mitra`: the dogfood claims.

How to test:
```sh
cargo test                       # everything, incl. LL(1), LR(1) build, fuzzer, dogfood
cargo run -p mitra-grammar --example sample -- 7   # see a generated program
cd tree-sitter-mitra && npm install && npx tree-sitter generate \
  && npx tree-sitter test && node check-golden.js
```

Red-team findings (fixed in the follow-up commit):
- Huge weights became `inf` and broke the round trip: numbers must now be
  finite.
- Error lines for unbound or doubly bound names pointed one token late.
- `-9223372036854775808` (i64::MIN) could not be written; now it can.
- `-(5)` printed as `-5`, which reads back as a literal: the fuzzer found it
  once the generator made `- ( 5 )`.
- The reference now lists the parser's checks beyond the grammar (at least
  one argument, distinct `∀` names, 64-bit integers, finite numbers) and
  says tree-sitter accepts a superset.
- Old-syntax wording in error messages and doc comments.
- The dogfood now records failures as `= false` evidence instead of
  stopping the test, and also covers the LL(1) grammar.

Red-team findings left open:
- The fuzz checks the parser against its own printer and two *recognisers*:
  a precedence bug shared by parser and printer would pass. (Hand checks
  of the main precedence cases found none.) A fix would be a second,
  independent AST builder, e.g. LALRPOP actions building the AST.
- The generator never produces invalid programs, so "the parser accepts
  more than the grammar" is only checked by hand.

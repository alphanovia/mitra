# P011: a text nested past the parser's depth budget

The parser reads a nested text by calling itself once per level: each
`(`, `{`, `!`, `if`, `match` or operand goes one level down. Past
`parse::Settings::depth` levels (2000 by default, twice simulation's
depth budget) it stops and says so, at the place it stopped, instead of
running out of stack. A text that deep is not a model a person writes;
it is most often a generated one.

## Example

    fn f(x: integer) -> y: integer { ((((((((((… 3000 times … x … )))))))))) }
    // error[P011]: the text nests deeper than 2000 levels here, the
    // parser's depth budget (`parse::Settings::depth`)

## Fix

Write the text flatter: name a part with `let x = e in …`, or split it
into functions. Or raise `parse::Settings::depth` (the CLI reads on a
256 MiB stack, room for far more than the default).

# M006: a claim that is not a truth

A claim must check to a truth. In a function it reads what the function
takes and gives; in a record it reads the record as `self`. An expression
written in place in a rule is read as a claim too.

## Example

    contract Positive<T: Number> {
        fn f(x: T) -> y: T;
        claim pos(a: T) = 0 <= f(a);
    }

    error[M006]: `pos` is not a truth
     --> Positive::pos
      |
      | 0 <= f(a)
      | ^^^^^^^^^ `0` is Int and `f(a)` is T
      = note: `<=` compares two numbers of one type: Int, Real, or one `T: Number`
      = help: Mitra converts no number; a T comes from a function that gives one, declared beside the others

The message shows the claim, underlines the innermost part that has no
type with the type of each of its arguments, says what that operation
takes, and helps when a whole number is the cause. When every part has
a type but the whole is not a truth, it says `this is Int` and
`note: it should be bool`.

## Fix

Mitra converts no number: `0` is an `Int`, `0.0` a `Real`. Write
`1.0` beside a `Real`. A `T` comes from a function the contract
declares, as Rust's num-traits `Zero` does:

    contract Positive<T: Number> {
        fn zero() -> z: T;
        fn f(x: T) -> y: T;
        claim pos(a: T) = zero() <= f(a);
    }

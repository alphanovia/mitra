# M020: an impl that does not fit its contract, or names no function

`impl Monotone<Real> for speed;` says that functions of the part fit a
contract: it names a contract of the model, gives one type for each of
its parameters, each within its bound (`T: Number` takes `Int` or `Real`),
and one function of the part for each function of the contract, in
order, each taking and giving what the contract's does with those types.
The contract itself is checked once, where it is written; an impl only
fits it. An impl names one function at least (flagged): the contract's
claims are read of the functions it names, so `for ()` would read none.

## Example

In the illustrative syntax of `docs/model.md`:

    contract Monotone<T: Number> {
        fn f(x: T) -> y: T;
        claim rises(a: T, b: T): !(a <= b) || f(a) <= f(b);
    }
    subject stone {
        fn speed(h: Real) -> v: Real { 2.0 * h }
        fn lit(h: Real) -> on: bool;
        impl Monotone<bool> for speed;    // error[M020]: `bool` cannot be `T: Number` of `Monotone`
        impl Monotone<Real> for lit;      // error[M020]: `lit` does not take and give what `Monotone::f` does
        impl Monotone<Real> for ();       // error[M020]: `for ()` names no function
    }

## Fix

Give a type the bound admits, and functions with the contract's types.

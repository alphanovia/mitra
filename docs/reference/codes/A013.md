# A013: a loop that never ends

Mitra remembers the values an `until` has carried. When a turn carries
values it had already carried, the loop can only go round again: it
stops at once with no value, instead of running to the step budget. An
example that needs its value fails; a claim is unknown. Either says
where the loop is, at which input, and which values came back. A value known only in part
(`Location { depth: 2, .. }`) is never taken for one seen before.

## Example

    fn halve(n: integer) -> k: integer {
        until(k: n, k <= 1) { k }
    } where {
        examples { (4) -> 1 }
        // finding[A013]: example 0: fails, at n = 4, the `until` in
        // `s::halve` never ends: what it carries, 4, came back after 1 turn
    }

A loop whose carried values never repeat, such as one that also counts
its turns, `until((k: n, steps: 0), k <= 1) { (k, steps + 1) }`, is not
seen: it runs to the step budget: A016 for an example, A007 for a
claim.

## Fix

The block likely forgets a step, here `k / 2`. If the loop is meant to
stop only for some inputs, say which in what the function takes.

# M034: a set of a rule whose range holds no point

A rule's set, `(a: 0..10)`, takes the whole numbers from its low end up
to its high end, the high end left out, as Rust's `0..10`. A range whose
low end is at or above its high end holds no point: an `all` over it
would be true of nothing and an `any` false of nothing. It is almost
always a slip, so check refuses it, as Clippy's `reversed_empty_ranges`
does in Rust.

## Example

    rule r: f::c |- all x in (a: 1..0): correct(f, x);
    // error[M034]: the conclusion: `a: 1..0` holds no point: a range is written low end first: did you mean `a: 0..1`?

    rule s: f::c |- all x in (a: 3..3): correct(f, x);
    // error[M034]: the conclusion: `a: 3..3` holds no point: a range leaves its high end out, as in Rust: did you mean `a: 3..4`, the one point 3?

## Fix

Write the low end first, or move the high end one past the last point.
A set that a `where` leaves empty is not known until its points are
listed: explain says so, [X013](X013.md).

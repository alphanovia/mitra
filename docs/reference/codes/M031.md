# M031: a claim `by induction` on what is not an input that is a tree

`claim c: … by induction t;` shows `c` on each variant of the input `t`
at once: where the function calls itself on a part of `t`, what that
call gives is read as keeping `c` there. That reading is sound only when
`t` is a tree (an enum that holds itself) and every call the function
makes to itself takes apart `t`, so the calls end.

## Example

    subject enum Tree { Leaf, Node(Tree, integer, Tree) }
    subject Trees {
        fn size(t: Tree, k: integer) -> n: integer {
            match t { Leaf => 0, Node(l, _, r) => size(l, k) + 1 + size(r, k) }
        } where {
            claim a: 0 <= n by induction k;
            claim b: 0 <= n by induction u;
        }
    }
    // error[M031]: `k` is integer, not a tree: `by induction` is on an input whose enum holds itself
    // error[M031]: `u` is no input of `size`: `by induction` names the input the claim is shown on

A claim of a record, which has no input, is not shown by induction.

## Fix

Name the tree input every self call takes apart: `by induction t`. Lean
writes the same with `induction t`, Coq with `induction t`.

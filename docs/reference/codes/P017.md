# P017: a name alone names a part at two levels

A name alone is looked up in the part where it is written, then in each
part around it, out to the top of the model, and among the parts its
part uses whole (`use A::B;`). When it names a part at two of these
places, Mitra does not choose: nothing hides anything.

Swift looks nested types up the same way but lets the nearest one win;
Rust needs `super::` or a `use`. Mitra asks for the whole path.

## Example

    subject agree {
        subject record Settings { points: integer }
        fn defaults() -> s: Settings { Settings { points: 64 } }
    }
    subject record Settings { depth: integer }
    // error[P017]: `Settings` names `agree::Settings` and `Settings`:
    // nothing hides another; write the whole path

## Fix

Write the whole path, `agree::Settings`, or `crate::Settings` for the
one at the top of the model. Or rename one of them.

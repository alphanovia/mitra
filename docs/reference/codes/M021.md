# M021: a model example that names no input or output, or states no output

An example of the model says what the model gives across parts, as an
end-to-end test would: at these inputs, these outputs. Each is named by a
function and the name of what it takes or gives, `stone::speed::h`. An
input is what a function takes, or what one with no body gives (the
world's value there, `sun::light::w`). An output is what a function
gives. Each is named once, on one side: a value on both would be its own
expected value. An example states one output at least: it says what the
model gives.

## Example

In the illustrative syntax of `docs/design/model.md`:

    examples {
        (sun::light::w = 850.0, stone::speed::h = 5.0) -> stone::speed::v = 98.1,
        (stone::speed::v = 1.0) -> stone::speed::h = 0.5,    // error[M021]: twice, an input it computes, an output it takes
        (stone::speed::h = 5.0) -> (),                       // error[M021]: it states no output
    }

A row `when Part::f(args) then v` names its function: it must be one of
the model, taking as many arguments.

    examples {
        given Sun::light() -> 2.0 when Stone::cool(5.0) then 10.0
        // error[M021]: `when Stone::cool(5.0)`: `Stone::cool` is no function of the model taking 1 arguments
    }

## Fix

Give inputs that functions take, or that functions with no body give, and
one output or more that functions give, none of them an input.

# M019: a function that calls itself, not on a part of its input

A function may call itself only on a part of one of its inputs, taken
apart by a `match` (structural recursion, as Lean and Coq take it), the
same input for every call: such calls end, because each is on a smaller
tree. Any other call to itself, or a cycle through other functions, is
refused: with no such call, every run of the model ends, and a function
is checked once, not at each call. Each function on a cycle is reported.

## Example

    subject enum Tree { Leaf, Node(Tree, integer, Tree) }
    subject calc {
        fn size(t: Tree) -> n: integer {
            match t { Leaf => 0, Node(l, _, r) => size(l) + 1 + size(r) }   // ends
        }
        fn bad(t: Tree) -> n: integer {
            match t { Leaf => 0, Node(l, _, r) => bad(t) }   // error[M019]
        }
        fn even(n: integer) -> e: bool { if n == 0 { true } else { odd(n - 1) } }   // error[M019]
        fn odd(n: integer) -> o: bool { if n == 0 { false } else { even(n - 1) } }   // error[M019]
    }

## Fix

Call the function on a part the `match` gives (`l`, `r`); write a
repetition over numbers as an `all` over a range, a `fold` or an
`until`; or leave the function opaque and give its examples.
